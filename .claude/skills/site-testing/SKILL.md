# site-testing — полная проверка сайта

Справка: `docs/testing/strategy.md`, `docs/testing/automation-matrix.md`, `docs/testing/human-review.md`.

## Шаги
1. `npm ci` (если нет `node_modules`). Браузер уже установлен в облачной среде — **не** запускать `playwright install`.
2. `npm run verify` — одна команда: e2e (desktop + mobile) → visual → audit → скриншоты → `review/index.html`.
3. Разобрать результат:
   - **Упали e2e** — открыть `test-results/artifacts/*/error-context.md` и скриншот падения, найти корень. Баг в сайте → сообщить автору (и починить, только если просили правку). Баг в тесте → исправить тест, не ослабляя проверку.
   - **Упал visual** — посмотреть `test-results/artifacts/*-diff.png`. Намеренное изменение → вынести на ручную проверку; случайное → регрессия, искать причину.
   - **Неожиданно прошёл `test.fail`** — известный баг исправлен: снять пометку, обновить `docs/known-issues.md`.
   - Аудит (`review/audit.json`) — сравнить с known-issues; новое → добавить KI-xxx.
4. Опубликовать `review/index.html` через Artifact (icon `checklist`) — это готовая страница, её не нужно переделывать.
5. Ответ автору (по-русски, коротко):
   - ✅ сколько автопроверок прошло, ❌ что упало (простыми словами), ⚠️ важные находки аудита;
   - 👩 ссылка на страницу и просьба пройти карточки «Проверь сама», затем нажать «Скопировать ответы» и прислать их;
   - чего робот не может проверить и почему (1–2 фразы, по `automation-matrix.md`).
6. Когда автор прислала ответы: каждое «Нужна правка» → задача (скилл `add-feature`), «Всё хорошо» по визуалу после изменений → `npm run test:visual:update` + коммит эталонов.

## Полезное
- Один тест: `npx playwright test -g "<часть названия>" --project=e2e-desktop`.
- Реальное воспроизведение видео (есть Google Chrome): `PW_CHANNEL=chrome npm test`.
- Отчёт с трейсами: `npm run report`.
- Посмотреть скриншот самому: Read на `review/screenshots/<секция>-<desktop|tablet|mobile>.jpg`.
