# Система тестирования

Цель: Claude проверяет **всё, что можно проверить машиной**, автономно и без участия человека,
а всё остальное превращает в короткий наглядный чек-лист со скриншотами, который автор проходит за 10 минут.

```
npm run verify
 ├─ 1. e2e (блокирует)        tests/e2e/      Playwright, Chromium, desktop 1280 + Pixel 7
 ├─ 2. visual (блокирует)     tests/visual/   сравнение секций с эталонами
 ├─ 3. audit (не блокирует)   tests/audit/    находки качества → review/audit.json
 └─ 4. review (не блокирует)  tests/review/   скриншоты → scripts/build-review.mjs → review/index.html
```

## 1. Функциональные тесты (e2e)
Каждая фича = свой spec: `page-load`, `navigation`, `lightbox`, `contacts`, `accessibility`.
Запускаются в двух проектах: **e2e-desktop** (1280×800) и **e2e-mobile** (эмуляция Pixel 7, touch).
Правила:
- Тест описывает **желаемое** поведение. Если оно сейчас нарушено (известный баг) — `test.fail(true, 'KI-xxx: …')` + запись в [known-issues](../known-issues.md). Когда баг исправят, Playwright сообщит «ожидалось падение, а тест прошёл» — снять пометку.
- Никогда не удалять и не ослаблять тест ради зелёного прогона.
- Google Fonts в e2e подменяются пустым CSS (быстро и не зависит от сети); в visual/review — отдаются из локального кэша `tests/fixtures/fonts`.
- Если браузер не может проверить что-то в принципе (H.264-видео) — тест добавляет аннотацию `human-check`, и она попадает на страницу ревью.

## 2. Визуальная регрессия
`tests/visual/sections.spec.ts`: 5 секций × (desktop, mobile) → `toHaveScreenshot` (допуск 2% пикселей).
Эталоны лежат в `tests/visual/__snapshots__/`. Изменил внешний вид намеренно →
человек смотрит новые скриншоты на странице ревью → только после «да» `npm run test:visual:update` и коммит эталонов.

## 3. Аудит
Не падает, собирает находки с уровнем важности: вылезание контента за экран (375/768/1280), узкие блоки,
заглушки, SEO/OG, шрифты, вес страницы, axe-core (все уровни), доступность лайтбокса, свайп.

## 4. Ручная проверка
См. [human-review.md](human-review.md) и [automation-matrix.md](automation-matrix.md).

## Доступность
- e2e (блокирует): у всех `img` есть `alt`, у `.gallery-btn` есть `aria-label`, нет **critical** нарушений axe, галерея открывается с клавиатуры.
- аудит (информирует): serious/moderate нарушения axe, фокус в лайтбоксе.

## Где смотреть результат
| Что | Где |
|---|---|
| Подробный отчёт Playwright (трейсы, скриншоты падений) | `npm run report` → `test-results/html` |
| Машиночитаемый итог e2e | `test-results/e2e.json` |
| Находки аудита | `review/audit.json` |
| Страница для человека | `review/index.html` (Claude публикует её как Artifact-ссылку) |

## CI
`.github/workflows/tests.yml` запускает `npm run verify` на каждый push/PR и прикладывает `review/` и отчёт Playwright как артефакты.

## Как написать тест для новой фичи
1. Файл `tests/e2e/<фича>.spec.ts`, первая строка — комментарий со ссылкой на `docs/features/<фича>.md`.
2. Использовать `openSite(page)` из `tests/helpers/site.ts` (ловит ошибки консоли и 404).
3. Локаторы — по роли/тексту/`aria-label`/id (`getByRole('link', { name })`), не по inline-стилям.
4. Проверять поведение, а не реализацию: «клик открывает нужную картинку», а не «display стал flex».
5. Для визуального блока — добавить секцию/скриншот и строку в `human-checklist.json`.
