# Как добавляется новая функция (цикл Compound Engineering)

> «Каждая единица работы должна делать следующую проще». 80% — план и проверка, 20% — код.
> Методология: [EveryInc/compound-engineering-plugin](https://github.com/EveryInc/compound-engineering-plugin).
> Реализовано скиллом [`add-feature`](../../.claude/skills/add-feature/SKILL.md).

```
 0. Прочитать ─► 1. Обсудить ─► 2. План ─► 3. Тесты сначала ─► 4. Код ─► 5. verify ─► 6. Ревью ─► 7. Человек ─► 8. Compound
      ▲                                                                                                          │
      └──────────────────────── уроки из docs/solutions/ читаются в начале следующей задачи ◄──────────────────┘
```

| Шаг | Что делаем | Результат |
|---|---|---|
| **0. Прочитать** | `CLAUDE.md` → файлы затронутых фич → `known-issues.md` → `grep` по `docs/solutions/` | понимание контекста |
| **1. Обсудить** (brainstorm) | Уточнить у автора цель и вид: что увидит посетитель, на каких устройствах, есть ли материалы (картинки, тексты). Не больше 2–3 вопросов. | требования в 3–5 пунктах |
| **2. План** | Файл `docs/plans/YYYY-MM-DD-<slug>.md` по [шаблону](../plans/_template.md): цель, затрагиваемые фичи, задачи с чекбоксами, тесты, ручные проверки, validation commands. | план, совместимый с ralphex |
| **3. Тесты сначала** | e2e-тест на новое поведение (падает — это нормально), строка в `human-checklist.json` для визуальной части. | красный тест |
| **4. Код** | Минимальная правка `index.html` в стиле файла (копировать ближайший блок). | зелёный тест |
| **5. verify** | `npm run verify`. Визуальные эталоны упадут, если вид менялся **намеренно** — это ожидаемо, не обновлять их сейчас. | e2e зелёные |
| **6. Ревью** | Перечитать diff как строгий ревьюер: адаптив (375px!), доступность (`alt`, `aria-label`), стиль, не задеты ли другие фичи, нет ли лишнего. Скилл `/code-review` по желанию. | исправленный diff |
| **7. Человек** | Опубликовать `review/index.html` как Artifact и дать ссылку. Автор отвечает «ок / правка». После «ок» — `npm run test:visual:update`. | одобрение |
| **8. Compound** | Урок → `docs/solutions/`; обновить файл фичи (строки, «Как изменить», «История»), индекс в `CLAUDE.md` и `features/README.md`; план → `docs/plans/completed/`; коммит + push. | знание закреплено |

## Правила
- Не начинать код без плана (для мелочей вроде «поменять текст кнопки» план — 3 строки в чате, без файла).
- Одна фича — один план — серия маленьких коммитов.
- Если во время работы найден чужой баг — не чинить молча: записать в `known-issues.md` и сказать автору.
- Если решение автора нужно, а его нет — сделать разумный вариант, явно отметить его в отчёте и в ручной проверке.

## Большие задачи → ralphex
Если в плане > 3 независимых задач, план можно выполнить автономно через [ralphex](ralphex.md): каждая задача — в свежей сессии Claude, после каждой — `npm run verify` и коммит, затем многоагентное ревью.
